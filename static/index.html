The Problem

Payment pricing isn't one percentage. Contracts contain tiers, caps, waivers, GST, and transaction-specific exceptions.

Reconciliation means checking those rules against every settlement. Manual review doesn't scale, so discrepancies go unnoticed.

Pipeline
01

Contract Ingestion

Upload the merchant agreement as a PDF or Markdown. Gateway-specific adapters normalize Razorpay, Stripe, and PayU contract structures so rules are processed uniformly.

Input: PDF / Settled CSV
02

Multi-Model Extraction

A single hallucinated tier silently corrupts all downstream math. We run a 3-pass extraction using Claude 3.5 Sonnet, OpenAI, and NVIDIA Nemotron.

If the models disagree during self-consistency checks, the rule's confidence score drops below our threshold and is flagged for review. If they align, we output a strict JSON schema that maps rules directly to source text:

{
            "DOMESTIC_CARD": {
              "pricing": "tiered_volume",
              "volume": {
                "0–10L": 2.00,
                "10L–50L": 1.75
              },
              "currency": "INR",
              "confidence": 97%,
              "status": "verified"
            }
          }
LLM: Claude / OpenAI / Nemotron
03

Deterministic Engine

Every settled transaction in the CSV is passed to the fee engine. No LLMs are used for math. Calculations run sequentially in pure code against versioned rules, ensuring we correctly price old transactions using historical rate windows (effective_from/effective_to).

Code: Fee Calculation & Rule Versioning
04

Audit & Disputes

Transactions are labeled (MATCH, LEAK, EXCEPTION, UNDERCHARGE). Misalignments generate drafted dispute claims citing the explicit source clause and tracking idempotency keys natively in SQLite.

Output: WAL Audit Store & Run Manifest
